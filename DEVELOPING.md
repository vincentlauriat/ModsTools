# Developing mods

## Layout of a mod

```
mods/<name>/
  .claude-plugin/plugin.json   name, version, description, author, optional "types" and "userConfig"
  hooks/hooks.json             { "modules": ["./register.ts"] }   (.tsx when the mod draws JSX)
  hooks/register.ts(x)         export const register: Register = (on, options) => { … }
  hooks/<logic>.ts             pure logic, unit-tested on its own
  hooks/*.test.ts(x)           tests run by `claude plugin test`
  types/index.d.ts             state contract (only when the mod uses $.state atoms)
  tsconfig.json                { "extends": "./.claude-plugin/types/tsconfig.json" }
  README.md
```

`.claude-plugin/types/` is generated by Claude Code when it loads the mod (API typings and the `tsconfig.json` the mod extends). It is gitignored.

## Checks

```sh
claude plugin validate mods/<name>   # manifest + what the module hooks and calls
claude plugin test mods/<name>       # the mod's tests, against the engine
tsc -p mods/<name>                   # once the mod has been loaded once (types laid)
```

Run every suite:

```sh
for m in mods/*/; do claude plugin test "$m"; done
```

## Hot reload while developing

Load the `plugin-authoring` skill in a Claude Code session: it names a session mods folder and asks once to enable hot reloading. Copy a mod there (excluding generated types) and it reloads at the end of each turn that edits it:

```sh
rsync -a --exclude '.claude-plugin/types' mods/<name>/ ~/.claude/dev-mods/<session-id>/<name>/
```

Or load the repo copy directly: `claude --plugin-dir mods/<name>` (watched in interactive sessions).

## Gotchas learned building these mods

- A helper that receives `$` must be a top-level function declaration, not a closure inside `register`, or `validate` refuses it.
- In tests, hooks registered with `on` stand for the engine and must return the event's result shape: `$` calls → `{ value }`, `prompt.submit` → `{ text }`, `turn.complete` → `{ text }`, `tool.call` → `{ result }`. One `on` per event per test.
- `key` is not kept on `Text` elements: find them by `{ type: 'Text', text }`; use `key` on Buttons.
- `turn.complete` and `tool.call` also fire for subagents (`e.agentId` set) — most mods skip those.
- `$.process.run` rejects on timeout or when the program cannot start: always catch.
- `userConfig` fields are string, number or boolean — no arrays (use comma-separated strings).
- `$.ui.status` holds one entry per plugin; `$.store` persists across sessions with no contract; `$.state` is per session and declared in `types/index.d.ts` (type exports only, no `export {}`).
- Never match English-only tool output: git may be localised, and output-compacting proxies such as RTK rewrite it.
- Prove a test bites: break the feature, watch the test fail, restore.

## Conventions

English code, comments and docs; short modules; pure logic separated from hooks; conventional commits (`feat:`, `fix:`, `docs:`).
